## 一、需求 → 设计映射

| # | 用户需求 | 设计落点 |
|---|---|---|
| 1 | Mac 生成临时秘密，含过期时间 | 主窗口"临时秘密"卡片：8 位短码 + 倒计时 + 时长选择（10m/1h/8h/24h） |
| 2 | 每次重启默认换，可选保持不变 | 「重启后保持此秘密」复选框，默认不勾=重启即换 |
| 3 | 可设永久秘密 | 独立"永久秘密"卡片：设置/修改/停用，掩码显示 |
| 4 | Mac 查看被连记录 | 「连接历史」窗口：时间/来源/秘密类型/时长/流量/结果，仅元数据 |
| 5 | 手机输入 Mac 的秘密即可连 | 主界面唯一必输项=秘密；服务器地址收进设置（保留默认值） |
| 6 | 按住说话，松开停止（微信式） | 底部拇指热区 PTT 大按钮：按下即传、松开即停，环状波形反馈 |
| 7 | 成败都有提示且不干扰 | 顶部横幅式轻提示（snackbar），2.5s 自动消失，不弹窗不打断 |
| 8 | 连接状态标记 | 顶部常驻状态条：LED 点 + 文案（未连接/连接中/已连接·设备名） |
| 9 | 设置里配服务器（IP 或域名） | 设置页"服务器地址"字段，域名与 IP 均可 |
| 10 | 多设备保存、单台激活传输 | "我的设备"芯片列表单选激活，切换即重连；设置页可增删 |
| 11 | 连接/传输有日志、数据 0 留存 | relay 与 Mac 端均零音频落盘（现状保持）；日志仅元数据 |
| 12 | 防止爆破（消息截断处按此理解） | relay 按 IP 滑窗限速 + 失败递增锁定；失败尝试全部落日志 |

## 二、关键决策与备选比较

### D1 临时秘密形态：短码 vs 长随机
- **A（选定）8 位 base32 短码**（如 `K7M-2QX9`，剔除 0O1lI）：熵约 40bit，人工可输可念；
  安全性依赖 D4 的限速兜底。
- B 64 位 hex：熵高但无法手输，违背"直接输入就能连"的核心诉求。否决。
- 结论：临时秘密用短码 + 短时效 + 限速；永久秘密建议 ≥12 位自设或生成，无短码需求。

### D2 认证模型：Mac 注册制（协议 v2 影响）
- **A（选定）Mac 为身份中心**：Mac 上线后向 relay 注册 {永久秘密哈希, 临时秘密哈希+过期时刻}；
  手机 AUTH 只带秘密，relay 查表路由到对应 Mac。多 Mac=多注册条目，天然支持 #10。
- B 保留 relay 全局 token + 秘密作路由键：改动小，但手机侧仍存在"服务器密码"概念，
  与"只靠秘密连接"诉求冲突。否决。
- 安全细则：relay 只存 SHA-256 哈希不存原文；过期由 relay 强制；**到期不中断已建立会话，
  仅拒绝新连接**（避免通话中途掉线）。

### D3 PTT 与免提并存
按住说话为默认交互（#6）；设置保留「免提常开」开关，兼容会议场景与 v1 用法。

### D4 防爆破（对应被截断的需求 #12）
- AUTH 失败按来源 IP 滑窗限速（建议 5 次/分钟），超限递增锁定（1m→5m→30m）；
- 锁定期内直接拒绝并记录 `rate-limited`；成功认证清零计数；
- 所有失败尝试落日志（时间/IP/原因），与连接历史同源。

### D5 数据留存边界
音频：relay 与 Mac 全链路内存转发，零落盘（延续 v1 设计）。
记录：relay 日志 = 时间/角色/IP/字节/时长/结果（不含秘密原文）；
Mac 连接历史 = 本地存储、上限 200 条、可清空。

### D6 PTT 按钮锚定底部拇指热区（2026-08-26 增补）
- **A（选定）底部锚定**：主屏唯一常驻大控件，下缘距屏幕底约一指宽（避开手势条），直径 ≥160px。
  单手握持时拇指自然弧正覆盖该区域，按压无需移动重心，长时间使用不易疲劳。
- B 居中大圆钮：视觉对称、与波形居中对齐更"好看"，但单手按压需手掌上移离开自然握持位。否决。
- 高保真验证稿：docs/ui-design/v2/android-ptt.html —— 仅保留说话相关元素（状态栏/连接状态/
  波形/PTT 钮/手势条），标题栏、设置入口、设备芯片等一律不进该屏。

## 三、自查（查漏补缺）
- [x] 临时秘密"保持不变"与"重启即换"的关系：勾选=持久化当前值直至过期/手动重生成；默认不勾
- [x] 临时与永久秘密并存：任一均可通过认证（relay 双哈希注册）
- [x] 手机切换目标设备：断开当前连接→以新秘密重新 AUTH，状态条全程可见
- [x] PTT 期间断网：松开即停采音，状态条转"重连中"，不静默丢帧假象
- [x] 历史隐私：记录仅存 Mac 本地；relay 侧日志不含秘密原文
- [ ] 开放问题 1：Mac 客户端技术栈（Python GUI / Swift / Tauri）未定，不影响本 UI 设计
- [ ] 开放问题 2：手机端"设备别名"来源——建议 Mac 广播主机名，手机首次连接自动命名
- [ ] 开放问题 3：永久秘密是否需要定期轮换提醒（建议 v2 不做，历史记录足以审计）
