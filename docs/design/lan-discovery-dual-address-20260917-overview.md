## 1. 背景与用户意图

用户指出三件事：

1. Android 的服务器地址全靠手输（或命中 `AudioStreamService.kt:468` 硬编码的
   `DEFAULT_SERVER = 43.139.226.138:9432`），它并不知道局域网里正在运行的 server；
2. 期望的傻瓜式流程：**默认扫描局域网发现 server，用户直接选；扫不到才手动填**。
   服务器地址拆成两个：**本地（局域网）与远程（公网），本地优先探测**；
3. Mac 端只保留 Tauri 客户端（Python 版 `mac-app/` 归档到 `backup/`），交互保持傻瓜式，
   不要各种复杂设置。

## 2. 发现协议选型（三方案对比）

| 方案 | 思路 | 依赖 | 代码量 | 可靠性 | 结论 |
|---|---|---|---|---|---|
| **A. UDP 探测/应答（自研）** | 手机广播探测串 → server 应答 JSON（UDP 端口与 TCP 同号） | Go 标准库 + Kotlin java.net，零新依赖 | 最小（两侧各约 100 行） | 部分 AP 会隔离客户端广播，此时扫描为空回落手动 | **采用** |
| B. mDNS/Bonjour | 标准协议，Android 有 NsdManager | Go 侧需第三方库，破坏 server 零依赖原则 | 中 | 标准化最好 | 否决（违背零依赖） |
| C. 纯 TCP 扫 /24 | 手机直接对网段 254 个 IP 做 TLS 握手探测 | 无 server 改动 | 小（手机侧） | 慢、耗电、无服务器语义区分 | 否决（成本高体验差） |

选 A 的补充理由：与本项目"无域名、自签 + TOFU、完全自研可控"的路线一致；发现应答
不承载任何秘密，泄露面只有"这里有一个 remote-voice server"。

## 3. 发现协议定义

- **探测包**：UDP 数据报，payload 恰为 ASCII `RV-DISCOVER-v1`（14 字节，精确匹配才应答）。
  目标端口 = server TCP 监听同号端口的 UDP（默认 9432）。
- **应答包**：单行 JSON + `\n`：`{"v":1,"name":"<主机名>","port":9432}`（UTF-8，≤256B）。
  发送方源地址即服务器 IP；`port` 为 TCP 服务端口，Android 据此拼 `host:port`。
- **节流**：server 对同一源 IP 每秒最多应答 1 次，防探测放大滥用。
- **开关**：server 新增 `-discovery`（默认开）、`-name`（应答中的显示名，默认主机名）。
  关闭只影响发现，不影响 TCP 服务。
- **Android 扫描**：枚举网卡 IPv4 子网广播地址 + `255.255.255.255`，各发 2 轮探测，
  收集窗口 1.5s，按 IP 去重；在后台线程执行，结果弹列表供选择。

## 4. Android 双地址模型与连接策略

- 全局配置拆两个地址（SharedPreferences `config`）：
  - `server_local`：本地局域网地址，可空；来源=扫描选择或手动输入；
  - `server`：远程公网地址，保留原语义，空值回落内置 `DEFAULT_SERVER`。
- **连接顺序：本地 → 远程**。每个地址独立超时（10s 连接超时不变）；
  网络级失败（超时/拒连/TLS）自动切下一个地址；认证类失败（AUTH_ERR、指纹不符）
  仍为致命错误直接停服——秘密错误换哪个地址都不会对。
- 自动重连每轮都从本地开始尝试（回到家里自动回到低延迟链路）。
- 状态条在拨号阶段显示「本地/远程」前缀，用户能看出当前走哪条链路。
- TOFU 信任按 `host:port` 隔离存储（`TrustStore` 现有机制不变），本地/远程是两份信任记录。

## 6. 三轮查漏补缺

**第 1 轮（接口）**：探测串带版本号 `v1`，未来不兼容改动换串；应答 JSON 未知字段
容忍（Android 用 `optString/optInt`）；应答 `port` 为整数而非字符串。

**第 2 轮（异常）**：未连 Wi-Fi/无 IPv4 路由 → 扫描立即返回空并提示；广播被 AP 隔离 →
扫描 0 结果，UI 提示回落手动；server 端 UDP 启动失败只记日志，不影响 TCP 服务；
`server_local` 填了无效地址 → 跳过本地直连远程，不报致命错误。

**第 3 轮（安全）**：应答不含证书指纹、设备秘密；节流防放大；TOFU 与发现解耦——
发现只给地址，信任仍由首次 TLS 握手建立；UDP 应答默认开但可用 `-discovery=false` 关闭
（面向"只允许公网入站"的部署）。
