# PLAN-035 启动与 Fn 权限提示

- 基线 `944a95d`
- 编写于 2026-11-24（Asia/Shanghai）
- 用户目标是在 README 开头交代 Mac 启动和 Fn 授权要求，让 App 在缺少条件时给出提示，并让已配对的 Android 在 Mac 后启动时自动接回。

## 实施

1. 在根 README 的构建步骤前列出启动顺序、Mac 可见连接状态、辅助功能授权位置和 Android 测试步骤。
2. Android 在中继确认目标离线、现有桥接断开或目录确认没有在线 Mac 时，提示在 Mac 打开 Remote Voice 并连接中继。点选离线条目也显示同一操作说明。
3. Mac 读取系统辅助功能授权，在启用 Fn 且缺少权限时在音频区显示常驻提示。应用窗口重新获得焦点时复核授权。保留音频和 Fn 设置的既有行为。
4. Android 开启「断线自动重连」时，目标 Mac 尚未上线或桥接已断开都进入等待状态，按逐步延长的间隔重新建桥。设置页保存该开关，关闭时保留点按重试。
5. 用真实中继验证两种启动顺序、桥接断开后恢复和关闭开关的行为。验证 Mac 授权显示条件和前端构建，更新测试包，提交并推送。

## 实施前复核

1. 目标 App 未启动和 Mac 网络中断都可能显示离线。Android 使用服务端返回的状态给出排查动作，目录还未加载时保持连接中反馈。
2. Mac 使用发送键盘事件时检查的辅助功能授权。收到 Fn 松开的物理监听权限独立，因此不能用监听失败推导联动状态。提示不请求授权，也不阻断音频连接。

实机排查发现，辅助功能列表记录着旧 App 的签名。列表勾选后，macOS 的 `tccd` 仍因代码要求不匹配拒绝运行中的新 App。README 和 Mac 提示须包含更新后移除旧条目、重新添加当前 App 的操作。

Android 真实中继联调发现，Go 按 v4 协议返回 `{ "macs": [...] }`，Android 原先只接受裸数组。修正解析以使用真实目录，同时继续接受原来可解析的数组。

Android 先启动时，中继返回 `invalid-target`，旧客户端将整次连接视为无法恢复。Mac 退出时，中继解除桥接并通知手机，但原手机会话等不到重新建桥。两条路径使用现有连接循环重新向同一目标发起桥接，等待 Mac 时退避上限为五秒。仅针对已选目标，并遵守自动重连开关。密码错误、证书变化及已有其他会话仍走原有处理；等待期间可照常停止服务。设置页原先只加载开关值，保存时一并写入。
