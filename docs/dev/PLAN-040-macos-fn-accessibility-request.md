# PLAN-040 macOS Fn 辅助功能授权入口

- 日期 2026-11-24（Asia/Shanghai）
- 基线 `6e5f1c2`

## 目标

目标 Mac 已能向前台窗口发送 Fn，正式应用的系统授权仍绑定旧签名。让用户从当前启动的 Remote Voice 向 macOS 请求辅助功能权限，并在系统保留旧条目时定位正在运行的安装包。

## 实施

1. 在现有 Fn 权限提示中加「请求授权」和「打开辅助功能」。第一个操作通过 `AXIsProcessTrustedWithOptions` 为当前进程发起系统请求。第二个操作打开系统辅助功能面板，并在 Finder 定位当前进程所属的 App。 [Apple 辅助功能授权接口](https://developer.apple.com/documentation/applicationservices/1459186-axisprocesstrustedwithoptions?language=objc)
2. 继续用 macOS 当前进程的权限结果决定 Fn 注入和提示显隐。返回应用时刷新权限。实体 Fn 监听失败的提示独立于发送权限。
3. 在 README 的使用说明补上入口和旧条目的处理方法。释放目标 Mac 上本项目可重建的调试构建缓存。系统盘构建空间不足时，将隔离构建放在另一个卷上的临时 APFS 映像。备份现有包、安装并启动新版。
4. 验证未授权、已授权和关闭联动的界面状态，以及两个按钮的行为。目标 Mac 复核实际系统请求指向当前安装包，真机经公网连接后复测 Fn 按住和松开。

## 自查

- 静态说明依赖手工找包，原生请求可以由当前进程发起。系统保留旧授权时，定位已启动的包仍然可用。
- 授权以系统检查结果为准。音频转发和已配对手机的自动重连独立于 Fn 权限。
- Fn 模式、默认值、手机配对信息和中继配置沿用现有行为。
