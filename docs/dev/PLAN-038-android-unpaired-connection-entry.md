# PLAN-038 Android 未配对时的连接入口

- 基线 `6d920ee`
- 编写于 2026-11-24（Asia/Shanghai）
- 用户希望 Android 从 Mac 获取配对信息并连接。Redmi 真机恢复 USB 调试后确认，手机已保存 `voice.gpt60.com:443` 的 HTTPS 地址，密码和目标为空，点按时没有发起登录。该手机使用 Android 13。

## 实施

1. 缺少中继密码时显示「未配对 · 点按扫码」。连接入口直达现有扫码页，用户可扫码或粘贴 Mac 的配对码。保留「＋ 添加」的手动输入路径。
2. 未配对时隐藏缓存的 Mac 条目，按住说话时提示先配对。启动时按原来的授权和设置自动连接，摄像头由用户点按后打开。
3. 验证新安装及仅保存地址的旧数据。确认扫码入口、空配置提示、带目标的配对与已有配置的重连。覆盖安装到真实 Redmi 后验证配对持久化、实际公网建桥与按住说话。Mac Fn 按下和释放使用桌面事件验收。
4. 验证完成后更新 APK 与文档，提交并推送。

## 实施前复核

1. 单纯补一条错误提示会多出一次找入口的操作。去扫码页可直接完成用户要求的流程，已有手动地址配置保留在添加菜单内。
2. 已保存密码的服务器可以先登录再选择 Mac。以密码是否存在判断能否登录，目标 ID 暂时为空时保留目录选择。
3. 真机覆盖安装保留配置。清空、旧数据和取消扫码场景在自有模拟器中构造，避免清理用户数据。权限弹窗由系统处理。

## 联调复核

- Android 35 模拟器的摄像头曾裁掉居中摆放在源图的一部分二维码。根据预览调整测试图后，使用现有相机流程自动识别和建桥。Android 12 使用设备运行时执行新旧 APK 的配对解析类，验证旧版错误及修复。
- 在 Mac 解锁后，真机传音未出现 Fn 事件。`tccd` 显示本次授权的静态代码解析到了临时目录里的旧备份。将这份备份压缩保存，并移出可解析的 App 路径，继续确认正式安装包的授权和 Fn 行为。
