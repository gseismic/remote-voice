# PLAN-036 Android 配对目标与桥接恢复

- 基线 `c4541b9`
- 编写于 2026-11-24（Asia/Shanghai）
- 用户希望修复审查提出的四条连接问题。已登记的 Mac 可以后上线，失效的配对目标应退回可选状态，单台 Mac 的失败和重试应保留其他桥接。

## 方案

沿用 v4 `LIST` 和每台 Mac 一条连接的结构。只调整几个界面分支会继续把单台 Mac 和整个服务的重试混在一起。服务按桥接保存连接状态，登录目录独立跟踪，状态栏按需要重新建立登录会话及当前掉线桥接。

1. 让中继客户端明确区分等待目标、网络断开、就绪和连接中。保留自动重连退避和原有服务级错误处理，将单条桥接被拒绝保留为该 Mac 的可重试错误。
2. 仅用当前登录会话收到的 `LIST` 判断等候中的目标是否还在目录。移除已经消失的桥接并更新选中目标。目录里的离线 Mac 继续按设置等待或允许手动重试。
3. Mac 条目先处理手机自己已连接的桥接，再检查占用，最后连接可用设备。服务隔离目录刷新后发生的占用竞争。
4. 关闭自动重连时，网络断开或 Mac 离线都可以点按状态栏恢复。只重建缺失的登录会话和当前待重试的桥接，其他正常桥接保留。切换当前目标时同步音频与 TALK 帧路由。
5. 使用 Android 模拟器与真实 Go 中继验证以上场景、Mac 晚上线、停止连接和 PTT。完成无后续修改的复审后发布 APK、记录结果、提交并推送。

## 实施前复核

1. v4 目录包含已登记的离线设备。启动时的本机缓存和未完成认证的连接无法证明旧配对失效。只有等待目标状态和当前会话目录缺少该 ID 同时成立才移除待重试的桥接。
2. 登录连接仅负责目录，桥接独立传输。网络错误和桥接拒绝保持在受影响的连接上，服务器登录认证失败、证书变化及采音初始化失败仍由服务处理。
3. 验证时记录每条桥接的服务端会话标识，检查误点忙碌设备及重试期间另一台 Mac 的会话持续有效。检查新旧客户端回调按会话代次隔离。

## 联调复查补充

- 服务端以映射生成目录。连接页按设备 ID 固定条目顺序，并在目录内容变化时更新列表，避免轮询期间点击的位置对应另一台 Mac。
- 当前目标掉线时，即使仅剩一个就绪的桥接，仍可横滑切到该 Mac。保活测试端按协议发心跳，区分应用断线和测试端空闲超时。
- 服务更新保存的目标时校验它仍指向当前选择，保护已经写入但尚未重启服务的新扫码目标。活动采音错误回到主线程核对桥接和代次，再决定是否停服。
