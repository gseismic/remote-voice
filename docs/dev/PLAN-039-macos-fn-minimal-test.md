# PLAN-039 macOS Fn 最小测试

- 日期 2026-11-24（Asia/Shanghai）
- 基线 `ee793c8`

## 目标

用两个可各自编译和运行的 macOS 小程序验证 Fn 按下和松开。发送器只调用 Quartz。接收器只观察自己的前台窗口，既能检查实体 Fn，也能检查发送器的事件。

## 实施

1. `labs/fn/fn-send.c` 用 Quartz 发送 `flagsChanged`。按下设置 Fn 修饰位，保持 2 秒后松开。发出前检查当前进程的按键发送权限，两条事件都创建成功后才开始。
2. `labs/fn/fn-receive.m` 创建 AppKit 窗口，只打印投递到此窗口的 Fn 事件、时间和来源标记，直接用 `clang` 编译。
3. 在目标 Mac 编译两份源文件，验证接收器和发送器各自的结果。有发送权限时，验证接收窗口收到标记匹配的按下、松开和约 2 秒间隔。再用同一接收器观察正式应用由 Redmi PTT 触发的 Fn，记录辅助功能授权对正式应用的影响。
4. 在 `labs/fn/README.md` 记录两份源码的独立运行方法和输出，记录结果，提交并推送。

## 自查

- 发送器使用与正式应用相同的事件类型、键码和标记，便于用同一个窗口验证。接收器无需全局监听权限。
- 事件构造和窗口收到事件分别判定，收不到事件时保留原始结果。源文件独立于应用构建和网络。
