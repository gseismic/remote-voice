# PLAN-041 Android 在 Mac 暂时被占用后恢复连接

- 日期 2026-11-24（Asia/Shanghai）
- 基线 `6e5f1c2`

## 根因与验收

公网中继于 17:03:39 返回 `peer-busy`，旧桥接于 17:03:51 释放。Redmi 开着自动重连，却一直停在「连接失败」。旧客户端把暂时占用视为认证终止，目录恢复空闲时也不会再尝试建桥。

已配对手机遇到暂时占用时显示等待 Mac 空闲。开启自动重连时，旧会话释放后应自动回到「已就绪」。关闭自动重连时，目标空闲后点按一次状态栏即可恢复这条桥。

## 实施

1. 让目标桥的 `peer-busy` 进入独立等待状态，复用网络重连的退避。保留离线 Mac 的短退避和其他认证错误的终止行为。
2. 在首页显示被占用及自动或手动恢复方式。保持已连接条目优先切换、忙碌条目点按只提示、其他桥接继续运行的约定。最新目录移除登记时清理等待桥接。
3. 用真实 Go 中继控制旧连接释放的时机，分别验证打开和关闭自动重连的结果，并确认已有桥接仍可传输。用 Redmi 覆盖安装和复测公网连接、扫码页和按住说话。
4. 发布通过验证的 APK，写入结果、提交并推送。

## 自查

- 服务端仍保持每台 Mac 一条桥接。客户端只在释放后获得有效建桥。
- 等待占用和等待上线有各自的状态提示，关闭自动重连时共用单桥重试动作。
- 认证、证书和目标删除判断沿用现有安全约定。
