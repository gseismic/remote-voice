# PLAN-033 公网 HTTPS 中继与扫码直连

- 基线 `d08e38d`
- 编写于 2026-11-24（Asia/Shanghai）
- 用户目标是在 Mac 配置一次 `https://voice.gpt60.com` 与服务器密码，Android 扫码后自动进入对应 Mac 的连接，显示状态并能立即按住说话测试。
- 部署目标为 `voice.gpt60.com` 已指向的现有 `ubuntu@118.193.40.160`。沿用现有 Nginx 的 80/443 和 Certbot，保留中继数据目录与 Mac 身份。

## 实施

1. 按 [接口设计](../design/https-scan-to-connect-20261124-overview.md) 增加 HTTPS 接入，复用 v4 数据帧。配置 Nginx 独立域名、Let's Encrypt 签发与续期加载。让公网 Mac 会话只使用预登记身份，在服务器本机保留管理登记入口。
2. Mac 接受 HTTPS 地址，配对码携带中继地址、密码与设备 ID。Android 按原地址模式保存配置，按服务器记录目标，扫码后启动或重启现有前台服务并连接目标 Mac。沿用现有连接状态及 PTT 门控。
3. 验证旧 TLS 连接、HTTPS 握手与 v4 登录/桥接、配对码解析与目标选择。构建两端，更新目标 Mac 与远程服务器。验证公开证书和续期、Mac 注册、模拟手机公网桥接与 BlackHole 收音。Android 验收跨至少两轮目录轮询，检查扫码入口、PTT 和停止连接。若手机调试连接可用，安装并验证真机扫码。
4. 记录结果，更新索引，提交并推送。部署变化和实测结果一并登记。

## 实施前复核

1. `9432` 与高位端口此前均不可达，公网 `80/443` 现已到达正在运行的 Nginx。独立虚拟主机能避免修改其他站点。证书由 Nginx 读取，续期无需向中继进程开放私钥。
2. 现有 v4 允许新 Mac 登记并通过 REGISTER 改写服务器密码。公网入口在认证前检查预登记身份，生产原生入口绑定回环。目标机已有局域网登记的设备凭据摘要，可经两台机器现有 SSH 连接迁入，不必读取 Mac 的设备密钥或修改服务器密码。新旧配对码与多 Mac 场景均复用服务器记录，不跨服务器复用控制目标。
