# PLAN-014：连接前自动扫描局域网 server（已撤销）

> **状态：已撤销（2026-09-18，用户决定）**。V3.2 拍板"只保留公网连接，本地仅用于测试"，
> 自动扫描/局域网发现不再进入产品（本计划不再实施，保留作历史记录）。
> 局域网测试的替代方式：把 server 地址直接填成局域网 IP（无需任何扫描）。
> 详见 docs/ui-design/v3/index.html 的 V3.2 决定条款。

对应设计：[../design/lan-discovery-dual-address-20260917-overview.md](../design/lan-discovery-dual-address-20260917-overview.md)（本计划为其行为补充：扫描从"设置页手动"升级为"连接前自动"）
用户期望：无论 Mac 还是 Android，连接时都应自动扫描出局域网可用的 server；且本地/远程是
**两条并行链路（两个分组），由用户显式选择、可随时切换**——扫描只服务于「本地」组
（结果仅填入本地组地址，不改变选择），**「远程」链路永不扫描**，直连配置地址。
此前实现只在 Android 设置页放了手动扫描按钮，启动流程不会自动扫——手机总是直连远程。

## 1. 行为定义（两端一致，V3.1 由用户拍板）

1. 连接目标 = 用户当前选择的链路（本地/远程），两端界面以分段卡/分组呈现，可随时切换；
   连接中切换 = 停止当前 + 连接新链路。
2. **仅当选择「本地」链路时才扫描**（UDP 探测，窗口约 1.3s，2 轮广播），状态提示
   "扫描局域网…"；扫描结果只填入本地组地址，**绝不自动切换用户的选择**。
3. 「远程」链路直连配置地址，永不扫描。
4. 所选链路连接失败：错误面板提供「重试本链路」与「切到另一条链路」两个动作——
   切换永远由用户发起。
5. 自动重连（RelayClient 内部退避）不重新扫描，沿用连接时选定的地址；重开应用/重启
   服务后按当前所选链路重连（选本地则重扫）。
6. Android 在无 wlan/eth 网卡（纯移动数据）时本地组跳过扫描，提示走远程。
7. 扫描发现地址与组内已存地址相同则去重，不重复拨号。
8. 局域网可能存在多台 server：扫描结果以蓝牙式列表呈现——在线的可点选；历史连接过但
   本次未发现的条目列出并灰显标注「离线」（不可直连）。设置页本地组常驻该列表；
   连接时发现多台则弹出列表由用户选一台（单台直连免选）。

## 2. Android（AudioStreamService）

- `startStreaming` 的网络装配段移入后台"准备线程"：先 `LanDiscovery.scan(1200ms)`（有
  wlan/eth 才扫），按「扫描结果 → KEY_SERVER_LOCAL 记忆 → 远程（空值回落 DEFAULT_SERVER）」
  组装 endpoints；全程校验 connectionGeneration，期间服务重启则丢弃结果。
- 状态文案：扫描中/发现本地服务器 host/未发现走远程。
- 手动扫描按钮与 `KEY_SERVER_LOCAL` 语义保留（记忆地址成为回落项）。

## 3. Mac（mac-app-tauri）

- 新增 `src/discover.rs`：std UdpSocket 广播探测 + JSON 解析；广播目标 = 255.255.255.255 +
  由默认路由源 IP 推导的 /24 广播；`scan/scan_on`（后者可测）。
- `controller.rs connect_inner`：连接前扫描，选定地址注入 `RelayClientOptions.server`，
  TOFU 指纹按选定地址取（`trusted_fingerprint`）；state.detail 标注「局域网发现/配置地址」。
- connect 命令改为后台线程执行（扫描阻塞约 1.3s，不冻结 UI 线程）。
