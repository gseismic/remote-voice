# PLAN-015: Mac 端低频连接设置移出首页（改弹窗）

- 日期: 2026-09-18 11:12
- 基线 commit: 9e07c5b
- 状态: 待实施
- 来源: 用户反馈——"mac端中，设置服务器地址不应该放在首页，这个是低频次需求"

## 1. 问题与现状认知卡

### 现状（docs/ui-design/v3/mac.html @ 9e07c5b）

Mac 首页卡片顺序:

1. PAIRING SIGNAL（配对秘密大码 + 复制/重新生成）——P1，正确
2. CONNECTION SETTINGS · 中继服务器（`mac.html:165-205`）——**问题所在**：
   - 服务器地址输入框、设备名输入框、"保存设置"按钮常驻首页（L167-174）
   - 其后才是中继服务器状态行（L176-185）和音频输出区（L187-204）
3. LONG-LIVED ACCESS 永久秘密（L207-226）——同为低频配置，**已用折叠降级**（L213）
4. SESSION LOG（L228-231）

### 痛点

- 服务器地址/设备名是"装好一次基本不再动"的配置，却以两个常驻输入框占据首页第二卡的黄金位置，与 P1 配对信号卡竞争注意力（一屏出现两个重量级卡片，违反"一屏一主行动点"）。
- 中频内容（音频输出、连接状态）被表单挤到视觉次要位置。
- 首屏纵向空间浪费约 170px，日志卡被推出视口。

### 用户意图

首页只保留高频/中频内容（配对秘密、连接状态、音频），低频的服务器地址/设备名编辑收进一个明确的入口，需要时才出现。

## 2. 方案对比

| 方案 | 说明 | 评价 |
|---|---|---|
| A. 首页保留只读状态行 + 点击弹出"连接设置"弹窗（**选定**） | 服务器状态（地址/已连接标签/RTT）是中频排障信息，保留一行只读展示；编辑收进模态弹窗 | 桌面应用惯例；状态可见性不损失；实现上是把现有表单平移进弹层，复用 `.field`/`.btn` tokens，改动最小 |
| B. 仿永久秘密做折叠卡 | 仍在首页占位 | 用户明确要求"不放在首页"；且与永久秘密形成两个抽屉，重复 |
| C. 独立设置页（Android 端模式） | 为两个字段开整页 | 过重；Tauri 单窗口还要引入导航返回，成本高于收益 |

[假设] 选 A：模态弹窗而不是常驻折叠，理由是用户明确表述"不应该放在首页"，且桌面端模态设置是成熟心智。

## 3. 目标信息架构（mac.html 首页）

1. PAIRING SIGNAL —— 不动
2. **RELAY SERVER · 中继服务器**（新，单行只读卡，整卡可点）：
   - 默认态: t1=`未连接`，t2=`点右上状态胶囊连接 · 点击本卡修改设置`
   - 已连接态: t1=`<地址>`+`已连接`标签，t2=`配置地址 · 点击本卡可修改`，右侧 RTT
   - 空态（未配置，原型以默认地址演示已配置态，但保留分支）: t1=`未配置服务器`，t2=`点击本卡填写地址`
   - 右端加「修改」小按钮明示可点（affordance），行悬停高亮
3. **AUDIO OUTPUT · 音频输出**（从原第二卡拆出，内容不变）: 音频输出说明行 + 下拉 + 电平表 + 状态行
4. LONG-LIVED ACCESS —— 不动
5. SESSION LOG —— 不动

## 4. 弹窗设计（连接设置）

- 遮罩 `.ovl`（fixed、点击空白关闭）+ 对话框 `.modal`（宽 ~400px，`--card` 背景、12px 圆角，复用现有 tokens）
- 内容: 标题区（sect CONNECTION SETTINGS + 「连接设置」+ 右上 ×）、服务器地址 `.field`、设备名 `.field`、
  说明文字（本地测试可填局域网 IP:端口）、错误提示行（校验失败显示，红色）、按钮区（取消 + 保存设置 pri）
- 关闭途径: ×、取消、点击遮罩、Esc（仅弹窗打开时）
- 保存逻辑**平移现有行为**（`mac.html:321-333`）: 校验 `host:port` → 更新地址/设备名 → 未连接仅提示、已连接自动断开重连 → 关弹窗 → 日志可见
- 打开时用当前生效值回填输入框；取消/Esc 不产生任何变更
