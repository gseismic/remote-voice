remote-voice · 客户端 UI 设计 V3（可交互原型）

LAN 自动发现时代的两端界面：Android 采音端 + Mac 接收端。
延续 V2「夜间音频控制台」体系（同一套 tokens），把 自动扫描 · 本地优先 · 链路可见 变成界面语言。
原型里所有按钮均可点击，直接操作即可走完两端的状态流转。

ANDROID · 可点击原型
手机端（主界面 + 设置）
点状态胶囊走「扫描→连接→传输」全流程；按住 PTT 说话；齿轮进设置：发现结果选用、LAN/WAN 双地址、设备增删、开关。单文件内导航，无需翻页。
MAC · 可点击原型
Mac 接收端
点状态胶囊：扫描→注册出秘密→模拟手机上线桥接；重新生成/复制秘密；音频下拉选未接入设备看缺失态；永久秘密折叠管理；会话日志实时追加。

ANDROID · SETTINGS
手机设置

四态切换：扫描 / 等待手机 / 桥接收流（电平表）/ 音频缺失。配对信号保持视觉最重，永久秘密降级折叠。

现状痛点 → V3 对策

端现状痛点V3 对策
Android浅色系统风与 Mac 端暗色控制台割裂；连接状态是一行小字；走哪条链路（局域网/远程）不可见；扫描只是设置页里的裸按钮统一暗色 tokens；状态升级为胶囊（大字 + LED + 链路标签）；扫描变为连接流程内建动作（雷达动画）；失败给可读原因 + 重试
Mac四张卡片均质排列、层级弱；桥接后缺音频可视化；无扫描/发现态；音频设备错误藏在最底部P1 配对信号唯一最重；新增连接目标卡（发现来源 + RTT + 音频电平表）；扫描横条；错误条紧贴音频卡并带重试
共性服务器地址是"手填表单"，与自动发现的产品方向相悖地址退居设置/详情；主路径 = 自动扫描 → 选用/直连，秘密照常配对
